# 数据流向、合规与交付形态

> 面向财税敏感数据，说明数据去向与两种交付形态。任何对客户输出的 AI 结论均需财税人员人工复核。

## 1. 数据流向（当前云 API 形态）

| 数据 | 存放/去向 | 是否出网 |
|---|---|---|
| 原始文档（政策/客户资料） | MinIO（自有存储/集群内） | 否 |
| 文档切块正文 | 向量化时**发送至 SiliconFlow**（embedding）；检索时候选片段**发送至 SiliconFlow**（rerank） | **是（片段文本）** |
| 向量 | Qdrant（自有） | 否 |
| 业务数据（租户/用户/文档元数据/对话/审计/反馈） | PostgreSQL（自有） | 否 |
| 用户问题 + 检索到的片段 | 生成时**发送至 DeepSeek**（LLM） | **是** |
| API Key / 密码 | 哈希后存库（bcrypt/sha256），明文不落库 | 否 |

**结论**：当前形态下，**文档片段文本与用户问题会发送到第三方模型 API**（SiliconFlow / DeepSeek）用于向量化、重排、生成；原始文件、向量、业务数据均留在自有基础设施。

## 2. 敏感数据合规提示

- 接入**客户敏感数据**前，须与负责人确认合规口径：是否允许片段文本经第三方 API。
- 需要"数据完全不出网"时，切换为**本地模型形态**：
  - embedding/rerank：本地 Xinference/TEI 跑 BGE-M3 + bge-reranker-v2-m3（改 `SILICONFLOW_BASE_URL` 指向本地，模型名/维度不变）
  - LLM：本地 vLLM 跑 Qwen 等（改 `LLM_MODEL` 经 LiteLLM 指向本地端点）
  - 架构已为此预留：模型接入经 LiteLLM/OpenAI 兼容抽象，切换只改配置不改代码。

## 3. 两种交付形态

| 形态 | 适用 | 部署 | 模型 |
|---|---|---|---|
| **多租户共享 SaaS** | 中小客户 | K8s（`k8s/`），租户级 RLS 隔离 | 云 API（SiliconFlow/DeepSeek） |
| **私有化独立部署** | 大客户/强合规 | docker-compose（`docker-compose.yml` + 三 Dockerfile）单租户 | 建议切本地模型（Xinference/vLLM），数据不出内网 |

两形态共用同一套代码；差异仅在部署编排与模型端点配置。

## 4. 使用规范（硬性）

- AI 生成的税务结论**必须经财税人员复核**后方可对客户输出（前端对话页与生成回答均已内置该提示）。
- 失效政策默认不参与检索/引用（`expire_date` 过滤）；如需查历史政策显式开启 `include_expired`。
